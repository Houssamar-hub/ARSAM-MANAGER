Système de Filtrage & Recherche Avancée

Ce document est un manuel complet expliquant le fonctionnement du filtrage dans l'architecture Node.js, Express, MongoDB et React de la plateforme ARSAM MANAGER. Il dresse l'inventaire complet de tous les filtres disponibles, de leurs requêtes, et détaille le code prêt à l'emploi.

1. Schéma du flux de filtrage (Full-Stack Data Flow)

1. UTILISATEUR      ➔ Saisie mot-clé ou sélection d'une option dans l'interface React
2. REACT STATE     ➔ Stockage dans des variables d'état (useState) avec Débouncing (300ms)
3. URL SEARCH     ➔ Génération d'une Query String via URLSearchParams (ex: ?status=in_progress&search=villa)
4. API BACKEND     ➔ Express intercepte les paramètres via req.query
5. MONGOOSE QUERY ➔ Construction dynamique de l'objet filter = {} avec opérateurs ($regex, $gte, $lte, $expr)
6. BASE MONGODB   ➔ Exécution optimisée avec tri et renvoi uniquement des lignes correspondantes

2. Inventaire complet de tous les filtres par module

A. Module Chantiers

Filtre Type Paramètre HTTP Opérateur MongoDB Rôle & Objectif
Recherche textuelle String search=nom_ou_ville $regex, $options: "i" Filtre simultanément sur le nom du projet et son emplacement géographique.
Statut d'exécution Enum status=in_progress filter.status = status Isole les projets : planned, in_progress, completed, suspended.
Conducteur de travaux ObjectId manager=67123... filter.manager = id Affiche uniquement les chantiers affectés à un chef de projet précis.

3. Implémentation Backend (Contrôleur Express & Mongoose)

Voici le modèle complet pour concevoir n'importe quel contrôleur de filtrage dans votre backend Node.js :

// server/controllers/chantierController.js
export const getChantiers = async (req, res) => {
  try {
    const {
      search,
      status,
      manager,
      minBudget,
      maxBudget,
      startDateFrom,
      startDateTo,
      sortBy = "createdAt",
      order = "desc"
    } = req.query;

    const filter = {};

    // 1. Filtre égalité exacte (Statut)
    if (status) {
      filter.status = status;
    }

    // 2. Filtre par conducteur de travaux (ObjectId)
    if (manager && mongoose.isValidObjectId(manager)) {
      filter.manager = manager;
    }

    // 3. Fourchette numérique (Budget)
    if (minBudget !== undefined || maxBudget !== undefined) {
      filter.budget = {};
      if (minBudget) filter.budget.$gte = Number(minBudget);
      if (maxBudget) filter.budget.$lte = Number(maxBudget);
    }

    // 4. Fourchette de dates (Calendrier)
    if (startDateFrom || startDateTo) {
      filter.startDate = {};
      if (startDateFrom) filter.startDate.$gte = new Date(startDateFrom);
      if (startDateTo) filter.startDate.$lte = new Date(startDateTo);
    }

    // 5. Recherche multicritère insensible à la casse
    if (search && search.trim()) {
      const safe = search.trim().replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
      filter.$or = [
        { name: { $regex: safe, $options: "i" } },
        { location: { $regex: safe, $options: "i" } }
      ];
    }

    // 6. Tri et exécution optimisée
    const sort = { [sortBy]: order === "asc" ? 1 : -1 };

    const chantiers = await Chantier.find(filter)
      .populate("manager", "name email role")
      .populate("createdBy", "name email")
      .sort(sort);

    return res.status(200).json({
      success: true,
      count: chantiers.length,
      chantiers
    });
  } catch (error) {
    return res.status(500).json({ success: false, message: error.message });
  }
};

4. Implémentation Frontend (React & Débouncing)

Pour garantir des performances fluides sans requêtes répétitives à chaque frappe de touche, on utilise un débounce de 300 ms :

// Exemple d'intégration dans un composant React
import { useState, useEffect, useCallback } from "react";
import chantiersApi from "../../api/chantiers.js";

export const ChantiersList = () => {
  const [searchTerm, setSearchTerm] = useState("");
  const [statusFilter, setStatusFilter] = useState("");
  const [managerFilter, setManagerFilter] = useState("");
  const [data, setData] = useState([]);
  const [isLoading, setIsLoading] = useState(false);

  const fetchData = useCallback(async () => {
    setIsLoading(true);
    try {
      const params = {
        search: searchTerm,
        status: statusFilter,
        manager: managerFilter,
      };

      const res = await chantiersApi.getAll(params);
      if (res?.success) setData(res.chantiers);
    } finally {
      setIsLoading(false);
    }
  }, [searchTerm, statusFilter, managerFilter]);

  // Déclencheur avec temporisation
  useEffect(() => {
    const timer = setTimeout(() => {
      fetchData();
    }, 300);
    return () => clearTimeout(timer);
  }, [fetchData]);

  return (
    <div>
      {/* Barre de recherche */}
      <input
        type="text"
        placeholder="Rechercher..."
        value={searchTerm}
        onChange={(e) => setSearchTerm(e.target.value)}
      />
      {/* Sélecteur de statut */}
      <select value={statusFilter} onChange={(e) => setStatusFilter(e.target.value)}>
        <option value="">Tous les statuts</option>
        <option value="in_progress">En cours</option>
        <option value="planned">Planifié</option>
        <option value="completed">Terminé</option>
      </select>
    </div>
  );
};

5. Filtrage Côté Serveur vs Filtrage Côté Client

Règle d'or de l'architecture ARSAM : Privilégiez toujours le filtrage côté serveur (via MongoDB et `req.query`). Cela évite de transférer inutilement des milliers de lignes sur le réseau mobile de vos équipes sur chantier. Le filtrage côté client (`array.filter()`) ne doit être réservé qu'à des listes statiques de moins de 100 enregistrements déjà chargées en mémoire.
